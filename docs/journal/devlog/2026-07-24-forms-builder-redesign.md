# docs/journal/devlog/2026-07-24-forms-builder-redesign.md
Issue:    — · branch worktree-forms-backend-hardening
Goal:     Session 3 of the Forms redesign — the visual rework of FormDetailView from the approved Artifact mockup: workshop layout, live preview, tabbed integration, sticky save, fields as the hero.
Done:     FormDetailView.vue rebuilt on a two-column grid (editor left, sticky preview+integration right). New components/forms/FormPreview.vue (renders the schema as a real, disabled form — the "what visitors see" panel) and components/forms/IntegrationPanel.vue (JSON/curl/SDK/Codegen tabs + copy, replaces six stacked code walls). Save + the "Unsaved changes" indicator moved into <PageActions> (teleports to the shell top bar); manual "← Back to Forms" link dropped (shell breadcrumb single-sources it via route.meta.parent). Schema Fields promoted to the hero (accent ring); field rows restyled as cards with a grip glyph, a numbered badge and a type chip, keeping the S2 reorder/remove controls. Migrated General inputs to .crm-input/.crm-label, "+ Add Field" empty state to EmptyState, and the hand-built submissions <table> to AppTable + Prev/Next pagination with font-mono/tabular-nums on data cells. Added FormDetailView specs for reorder + live-preview render (web 58 -> 60).
Why so:   Extracted only FormPreview and IntegrationPanel (read-only, clean string props) and kept the field editor inline rather than a FieldCard component — a FieldCard would need v-model/emit plumbing or nested prop mutation for every subfield, whereas inline v-model on the local `schema` array is trivially correct. "Required" stays on AppCheckbox (the sanctioned primitive) rather than a bespoke switch — there is no Switch primitive and inventing one would fight the design system for a purely cosmetic win. Right column is lg:sticky so the preview/endpoint stay in view while editing a long field list.
Failed:   No blocker this session. Note the S2 gotcha still applies: the design-guard `\bconfirm\(` rule means any useConfirm handle must not be named `confirm` (kept `confirmAction`).

Session 5 — decide/wire the `select` field type and collapse the field-type list to one source. Optional: real drag-and-drop for field reorder; a Switch primitive if one is added to ui/.
