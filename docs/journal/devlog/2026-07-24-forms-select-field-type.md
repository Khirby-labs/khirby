# docs/journal/devlog/2026-07-24-forms-select-field-type.md
Issue:    — · branch worktree-forms-backend-hardening
Goal:     Session 5 (final) of the Forms redesign — resolve the `select` field-type drift by wiring it end-to-end, so the shared type, validator, DTO and builder all agree.
Done:     Decided to implement (not remove) select. packages/forms-client: FormFieldDefinition gained `options?: string[]`; validateByType now takes options and, for select, rejects a value outside a non-empty options list ("must be one of: …"). apps/api: FormFieldDto gained optional `options: string[]` (@IsArray/@IsString each); FormsService FormSchema type carries options. apps/web: FORM_FIELD_TYPES now includes 'select'; the field card shows a comma-separated Options editor when type === 'select' (setOptions splits/trims/filters into field.options); validateBeforeSave blocks save when a select field has no options. Specs: forms-client validate.spec (option-membership accept/reject), form-field-templates.spec (FORM_FIELD_TYPES contains select), FormDetailView.spec (options editor renders + save carries edited options). forms-client 11 -> 13, web 62 -> 64.
Why so:   select was already half-wired — present in @crm/types and (since S1) in the runtime validator and the DTO's @IsIn list — but unreachable in the builder, so finishing it removes the three-way drift the review (M4) flagged, versus deleting a documented, type-level feature. Put option membership in validateByType (passing field.options) rather than a separate loop branch, keeping all select rules in one place. Options editor is a comma-separated input, not a repeater — simplest UI that round-trips cleanly through the by-value dirty snapshot; a richer editor can come later.
Also:     Running the dev server to review the work surfaced a pre-existing bug (present on main, not from this plan): AppSelect passes option values straight to Reka's SelectItem, which throws on an empty-string value — the SAME trap fixed for roles in 2ca9b3b. The Forms pages still used value:'' — the builder's "Apply template…" option and the analytics "All forms" option — crashing both views on mount. Fixed here: the builder drops the empty option and relies on AppSelect's placeholder; analytics uses an ALL_FORMS='__all__' sentinel mapped back to "no filter" when building the query.
Failed:   Nothing abandoned. Left server-side "select requires options" unenforced at the DTO layer (options stays optional there) — the builder blocks it pre-save and the runtime validator is lenient when options is empty (accepts any string), which is the safe direction for legacy/SDK-authored forms.
Next:     Forms redesign plan (S1–S5) complete. Open the MR to main. Possible follow-ups outside this plan: real drag-and-drop reorder; a Switch primitive; re-point the view specs at MSW once that harness lands (locked web-p0-msw-specs worktree); consider a DTO-level "select needs options" rule if authoring moves off the builder.
