# i18n rules (apps/web)

> **Status:** policy adopted 2026-07-24. The runtime (`apps/web/src/i18n/`) is built by the
> i18n foundation session. If that directory does not exist yet, this file describes the
> target, not the current tree — don't import from it.

Architecture and rationale: `docs/adr/0011-i18n-architecture.md`.
**How to actually write the strings: `docs/i18n-copy-guide.md`** — voice rules per language,
the frozen glossary, worked examples. Read it before writing any user-facing string.
To fill a namespace, use **`/copy <namespace>`** (dispatches the `copywriter` agent); don't
hand-write batches of copy in the main session.

## Two locales, both first-class

`pl` and `en` ship together and are **written natively for their own reader** — neither is a
translation of the other. `en` is only the technical fallback, so a missing key stays readable
to a developer.

Resolution order, and the order matters: **`localStorage` → `navigator.language` → `en`** decides
the first paint, then the **account's `users.locale`** wins as soon as the session is known and is
mirrored back into `localStorage`. Boot must never depend on `auth.user` — `/login` and `/404`
render before a session exists — and a `null` account locale means "no choice made", so it never
overwrites the browser's. An explicit choice in Settings writes both.

Intent that isn't recoverable from the key path goes in
`apps/web/src/i18n/messages/_context/<namespace>.json`, one line per key. Without it, whoever
writes the second language has only the first language to copy — which is exactly the calque
we're avoiding.

## Copy rules with teeth

- **Sentence case everywhere, buttons included** — `Change password`, `Zmień hasło`. Existing
  Title Case (`Save Changes`, `Add Member`) is legacy; fix it as you migrate the view.
- **Polish is impersonal.** No `Twój`/`Ty` (only `Zaloguj się` is exempt). Headings are nouns
  (`Zmiana hasła`), actions are imperatives (`Zmień hasło`), confirmations are infinitives
  (`Usunąć „{name}"?`).
- **Polish quotes are `„…"`**, English `"…"`. Straight `"` never ships. Real `…`, not `...`.
- **Errors: what happened + what to do.** No apologies, no "we", no blame.
- **Glossary is frozen** — `lead` and `pipeline` stay English, `wtyczka` / `zgłoszenie` /
  `etap` / `opiekun` are Polish. Don't re-decide per view; change the guide instead.

## Keys and structure

- `<namespace>.<block>.<element>`, camelCase leaves; namespace = feature directory.
- A key names the string's **role**, never its text: `common.actions.save`, not
  `common.saveButtonText`. Copy changes; roles don't.
- `common.*` is earned: 3+ call sites across 2+ features. Otherwise it stays in the feature.
- Never build a key by concatenation, except from a closed union the guard can enumerate.
- Avoid key paths that collide with protocol identifiers — `lead.created` is an SSE event type.

## Paired rules — every "don't" has a "do"

| Don't | Do instead | Because |
|---|---|---|
| Call `t()` in a module-level const | Store a `*Key` field; translate in a `computed` | Imports run before `app.use(i18n)`; `t()` returns the key and freezes the boot locale |
| Put copy in a `withDefaults()` default | Require the prop, or resolve it in a computed inside the component | Defaults evaluate outside a component instance |
| Assemble a sentence from fragments or DOM nodes | One message with named params; `<i18n-t>` when markup is inline | Word order and case endings aren't portable |
| Interpolate an enum into prose | A whole sentence per branch | `Włączona` vs `Włączony` — adjectives must agree |
| Render a DB token as a label, or lean on `capitalize` | Map the token to a key; keep the raw value for logic | `text-transform` is not localization |
| Translate persisted or user-entered data | Localize the picker; store the English seed | Stored data must not depend on the operator's UI language |
| Bake a glyph into a message | Glyph in markup, words in the message | Arrows flip under RTL; `✓` is not a word |
| Translate a language name in the switcher | Render the endonym raw — `English`, `Polski` | A reader must recognize their own language |
| Pass a locale tag or Intl options at a call site | `d(value, 'dateShort')` / `n(value, 'currency')` | Named formats keep every screen consistent |
| Write a count without a plural form | `t(key, count)`, always | English looks right at 1 and wrong at 2 in Polish |
| Throw a translated sentence through error plumbing | Throw a code; translate at render | A travelling message gets re-displayed and double-translated |
| Register a locale that's partially translated | Finish it on a branch, then add the registry row | Production fallback reads as a bug to users |
| Map backend labels to keys with a table in the SPA | Ship a stable `*Key` **and** the English literal from the backend; resolve via `useServerText()` | A third-party plugin the SPA has never seen stays readable instead of rendering a raw key |
| Localize a value that a form writes back | Localize read-only surfaces; bind the **stored** value in any editor | Saving the rename input would persist Polish into `pipeline_stages.name` |
| Translate a seeded row unconditionally | Translate it only while it still equals the seed literal from `@crm/types` | Once an operator renames it, their words must win and keep winning |

## Tests

Per ADR-0010, assert at the boundary — and here the boundary is the rendered string.

- **Mount with the real i18n instance** (`src/test/i18n.ts` → `mountWithI18n`). Never
  `global.mocks.$t`, never a key-passthrough stub: the stub *is* the bug it would hide.
- **Assert resolved copy, never keys.** A deleted key must fail a spec.
- Parity (en/pl key sets identical, no empty values) and plural rules are **pure units** —
  no mocks are possible, so no tautology is either.
- One boundary spec per locale switch: choose `Polski` → Polish copy in the DOM,
  `<html lang="pl">`, `localStorage` written, and a reload keeps it.
- Don't retreat to `data-testid` to dodge copy changes. Querying by visible text is the
  property worth keeping — update the expected string instead.

## Gate — and which half of it the compiler actually covers

Two mechanisms, and it matters which does what (both verified, not assumed):

- **`vue-tsc` gates locale *completeness*.** `messages/pl/index.ts` ends in
  `satisfies MessageSchema`, so a key missing from Polish — or present only in Polish —
  fails the typecheck.
- **`pnpm lint:i18n` gates everything else**, including **key existence**. vue-i18n's typed
  messages give autocomplete, but its `t(key: string)` overload still accepts any string, so
  `vue-tsc` does **not** catch `t('settings.nope')`. The guard does.

`pnpm lint:i18n` runs inside `pnpm verify` and checks: locale parity, empty values, three-dot
ellipses, straight quotes and Title Case in `pl`, Polish quotes leaking into `en`, missing
context notes, unknown `t()` keys, **keys declared outside `apps/web`** (a `labelKey` /
`descriptionKey` / `displayNameKey` / `navLabelKey` in `plugins/` or `packages/` must resolve in
`en/` — otherwise the fallback silently renders the English literal and the screen merely looks
untranslated), and the migrated-file ratchet. A missing translation is a red gate, not a silent
fallback — that's why the guard exists before the copy does.

Known limit, stated on purpose: the ratchet parses `<template>` and attributes only, never
`<script setup>`. Literals passed to `toast.success()`, `useConfirm()` or a thrown `Error` are
a review item, swept explicitly in the close-out session.
